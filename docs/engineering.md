# Engineering baseline

Updated: **2026-10-29**. These choices implement the user's explicit tooling requirements and current official extension guidance. They do not establish that the product is finished or that every upstream compatibility claim has been verified.

## Extension framework and language

Use **WXT 0.21.5** with strict TypeScript, following WXT's official entry-point/project layout and browser-target builds. Keep Manifest V3 explicit for both browsers. WXT generates the product manifests; the independent inference lab's manifests are only experimental fixtures. Sources: [WXT project structure](https://wxt.dev/guide/essentials/project-structure.html), [browser targeting](https://wxt.dev/guide/essentials/target-different-browsers.html), [TypeScript configuration](https://wxt.dev/guide/essentials/config/typescript).

Type-check page code and workers against their respective browser environments. Share typed message contracts and validate messages at trust boundaries. Build success does not prove browser behavior or worker/audio lifecycle.

## Bun throughout

**Bun 1.4.4** is the checked baseline and the latest stable release listed by Bun on the research date. The 1.4 release and 1.4.1–1.4.4 release notes were reviewed for current capabilities. Sources: [Bun 1.4](https://bun.com/blog/bun-v1.4), [1.4.1](https://bun.com/blog/bun-v1.4.1), [1.4.2](https://bun.com/blog/bun-v1.4.2), [1.4.3](https://bun.com/blog/bun-v1.4.3), [1.4.4](https://bun.com/blog/bun-v1.4.4).

- One Bun workspace and `bun.lock`; frozen installs for reproducibility.
- WXT runs under Bun, with Bun forced for package executables.
- Native `bun check` for TypeScript, and `bun test` for first-party tests. The TypeScript package serves framework/editor compatibility, not a separate checker process. Source: [Bun type checking](https://bun.com/docs/runtime/check).
- Native `bun fmt` for formatting/import sorting, with tabs, double quotes, no semicolons, LF, and a 120-column width. Ignore Markdown, generated files, and upstream vendor code. Source: [Bun formatter](https://bun.com/docs/format).
- `Bun.build` for the standalone inference experiment; WXT keeps its supported framework pipeline. Source: [Bun bundler](https://bun.com/docs/bundler).
- Bun-native file streams/hashing, shell operations, subprocesses, and Chromium automation in first-party tooling. Do not add replacement packages for built-in capabilities. Source: [Bun WebView](https://bun.com/docs/runtime/webview).

The install configuration intentionally follows `~/projects/talqo/bunfig.toml`: isolated linker, global store, a one-day minimum release age, and matching formatting/import groups. No Tailwind configuration is added without a Tailwind use case.

The browser extension itself uses browser APIs and bundled browser-compatible code. Development-only Bun APIs must never leak into browser entry points.

## UX, accessibility, security, and release guidance

Follow Mozilla's principles for focused extension functionality, contextual actions, clear state, predictable onboarding, and browser integration. Apply them to the selection context menu, playback bar, and deliberate voice download/preview/delete flow. Source: [Mozilla extension UX best practices](https://extensionworkshop.com/documentation/develop/user-experience-best-practices/).

Use supported browser UI surfaces and minimum permissions. The requested in-page bar does not imply access to native browser chrome or protected PDF viewer internals. Source: [Chrome extension UI surfaces](https://developer.chrome.com/docs/extensions/develop/ui).

Bundle executable assets, keep CSP strict, and verify Firefox/Chrome packaging and review policies. Accessibility targets applicable WCAG 2.2 AA criteria, including keyboard access, focus, labels, contrast, and useful status/error feedback. Detailed sources and feasibility gates are in [research.md](research.md).

## Evidence required before release

The development prototype has scoped product probes for local speech, model management, word highlighting, and PDF rendering. These do not prove native entry, complete benchmark fidelity, the 1-second warm / 2-second cold budget, background lifecycle, Windows, physical GPU recovery, or the 4-core/8-GB baseline. See [current acceptance status](feasibility-status.md). All three user benchmark URLs remain mandatory.

## PDF implementation

The approved PDF surface opens in a new extension tab and preserves the original document tab. PDF.js 6.4.299 and its worker, CMaps, standard fonts, image decoders, and license are packaged locally. Only the requested source PDF is fetched; the viewer does not execute document JavaScript. Text runs retain source offsets; visible pages render canvases and text layers as needed. Offscreen word highlights first prepare their target text layer. Native selection matching refuses missing/ambiguous matches instead of silently reading the whole PDF.

The CSP keeps executable code restricted to self, with WASM compilation allowed. PDF loading needs HTTP/HTTPS connections to the user-selected document origin; this is a connection policy, not a permanent host permission. The production manifests retain activeTab-based access. The cached-thesis rendering probe does not prove native PDF activation or cross-origin authenticated fetching in every browser. Sources: [PDF.js examples](https://mozilla.github.io/pdf.js/examples/), [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html).

## Feedback fixes and runtime investigation — 2026-10-30

- The reading overlay must not mutate page root padding or margins. Its height comes from the bar's bounding box, not the iframe document's scroll height (which can feed its viewport height back into resizing). Repeated toolbar activation focuses the existing controls; context-menu Read selection still replaces the source. Voices/settings remain available in the bar and through the browser's Options menu.
- Markdown block boundaries are sentence-navigation boundaries. ICU sentence segmentation is applied within each block, preserving original source offsets. A shorter first utterance reduces initial synthesis work; later chunks remain bounded and read ahead.
- PDF access needs separate treatment: `activeTab` on the original PDF does not imply the new extension reader can bypass the document site's CORS policy. On a failed fetch without a site grant, the reader offers an explicit, user-gesture-bound request for that origin alone. Declared optional host patterns grant no access at install time. See [Chrome host permissions](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions) and [Mozilla optional host permissions](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/optional_host_permissions).
- Pronunciation setup loads only the selected language (plus eSpeak's required English core) and overlaps model-session creation. Read-ahead jobs carry a cancellation generation; recently synthesized clips are cached within the live engine, bounded to 12 clips/8 MB and cleared on disposal. Reading text is not written to diagnostics or storage by this cache.
- ONNX Runtime uses up to four threads only when the actual worker is cross-origin isolated; embedded controls on ordinary pages normally are not, so the CPU path remains single-threaded there. Do not present the thread-selection code as proof of multicore inference. See [ORT threading requirements](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html).
- GPU selection requests a high-performance hardware adapter and rejects software fallback adapters; runtime initialization/inference failures retry CPU. Performance diagnostics stored locally as `lastSpeechPerformance` contain model/backend/timings, never reading text. First-buffer readiness is distinct from audible playback, especially if autoplay requires Play. A physical GPU still needs direct validation.

### Reusable inference host and script lifecycle follow-up

The final implementation moves synthesis ownership out of the page iframe. Chrome's bundled offscreen document uses COOP/COEP and the `WORKERS` reason; Firefox runs its model worker from the extension background page. Audio, controls, and source lifetime remain in the reading tab, so its navigation/closure still stops playback. Only the explicitly installed model is loaded. After a reader disconnects, source-text/clip caches are cleared; the model may remain in memory for up to two minutes. Reconnection reloads the chosen voice before sending synthesis jobs. Late replies to replaced or closed owners are rejected in the host and covered by meaningful tests.

Chromium runtime messages use JSON serialization, so PCM crosses the browser broker as bounded Base64 bytes and is reconstructed into Float32Array without JSON-number expansion. Worker inference itself still uses transferable buffers. The background validates sender extension protocol/host/page and speech command sizes; executable code remains bundled. This adds only Chrome's internal `offscreen` permission, no external app or service. Sources: [Chrome offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen), [Chrome isolation limitations for embedded frames](https://developer.chrome.com/docs/extensions/develop/concepts/cross-origin-isolation), [Mozilla's open extension-isolation issue](https://bugzilla.mozilla.org/show_bug.cgi?id=1673477).

WXT invalidates an old content-script context before reinjection. A bare global singleton flag cannot prevent the old runtime message listener from surviving: explicitly remove that listener on context invalidation. Normal activation now sends to the existing reader first, injecting only if there is no receiver. Page root padding/margins are never modified. Repeated activation reveals the existing session; the PDF toolbar action similarly focuses an existing reader tab for the same source.

The experimental session sweep favored basic graph optimization with CPU prepacking disabled on this VM; cold start remains over budget. Keep that limitation visible. The GPU diagnostic records the selected execution provider and fallback reason; without hardware measurements it is not a per-operator GPU-utilization claim. Firefox currently lacks the needed extension isolation mechanism for this threaded-WASM path; do not add unsupported manifest flags or tell users to weaken browser security settings.

### Playback readiness and voice-store consistency — 2026-10-30

The bar starts in a compact loading/setup state, with playback controls hidden until a catalog voice is actually available. Installed IDs are requested from the extension-owned background store; the embedded frame does not query IndexedDB. Invalid saved model/speaker choices fall back to a real option. Explicit Download/Delete completion publishes a small versioned `voiceChange` record through extension storage, whose change event updates the waiting bar and evicts a deleted voice from the inference host. Firefox's embedded page missed the previous runtime-broadcast update; both product probes now start without a voice and verify the live installation transition, stale-preference recovery, and final-voice deletion.

Normal playback keeps its status available to assistive technology without a permanent extra row. Preparing/gesture/error feedback is visible. Content height and state-dependent preferred width are sent explicitly to the parent; the iframe never measures its own viewport as content height. Closing guards pending initialization and voice refreshes from starting new work. A deleted voice is identified by the requested model even while its worker is still loading, not by potentially stale diagnostic metadata.

### Slow-download failure handling — 2026-10-30

The old voice download used one five-minute abort signal for lock waiting, configuration/model transfer, verification, and storage. That could discard a healthy slow transfer and its UI error was below the entire model list. Configuration and weights now share a bounded streaming downloader: the two-minute inactivity deadline resets on incoming bytes; there is no total-transfer deadline, and verification/storage are outside the network watchdog. Cancellation keeps its abort reason. Truncated, oversized, HTTP-failed, stalled, and dropped transfers fail before installation, while pinned configuration/model hashes still gate storage.

Download errors remain beside the model with the existing action changed to Retry. The page status announces the error once, and the action references its inline explanation; no duplicate alert region or dialog is added. Filtering preserves the result and an active download's progress. Retrying clears the old error, successful installation removes it, and completion processing is labeled Finishing download. Keyboard focus survives the row refresh.

### PDF selection sentence boundaries — 2026-10-30

Selecting the MUNI abstract inside our PDF reader reproduced spoken “dot” at four sentence boundaries. PDF.js positions text spans and line breaks visually; their concatenated DOM text omits spaces, so the generic page-selection walker produced text such as `workflow.This`. The bundled English phonemizer interpreted the joined text as a dotted expression even with punctuation announcements disabled.

PDF selections now take their exact character boundaries from the DOM range and slice the existing PDF text/run map. This preserves extraction whitespace, partial-word boundaries, and the source offsets used for highlighting. Native-viewer selection matching shares the same slicing implementation. Punctuation, URLs, and decimal numbers are unchanged.

`punctuation.test.ts` exercises the bundled browser phonemizer and production token mapping: the dot in `consensus.app` retains the same spoken phoneme IDs as the word “dot,” while the period in `workflow. This thesis` produces a pause. Its positive control reproduces the unwanted spoken dot when that space is missing. The MUNI browser probe also selects the real `Consensus.app` text through the PDF selection path to catch punctuation or whitespace changes.

The shared PDF browser regression selects the actual abstract through the reader message handler, checks the complete selected text against the mapped PDF text, verifies a selection with partial words at both ends, verifies highlighting after a sentence boundary, and rejects a collapsed selection. It runs in the Chrome PDF probe and Firefox product probe. Chrome 156 and Firefox 158 passed against the cached original MUNI PDF. The bundled `en-us` phonemizer emitted four standalone-period word events before the fix and zero with the corrected abstract. This verifies pronunciation input and source mapping; it is not a new neural-audio quality or latency measurement.

### Selection precedence on Play — 2026-10-30

The player asks its source host for a current selection before starting or resuming playback. A nonempty selection replaces the reading text and sentence chunks, clears the old synthesis/audio queue before resuming the audio context, and starts at the selection's beginning. A missing selection preserves the existing scope and paused position. The host consumes a selection once; replay and sentence navigation retain its boundaries. Selection failures are surfaced rather than falling back to unrelated content. Pause does not change the reading scope.

Web selections use the existing DOM extraction and run mapping. PDF selections use the complete PDF text/run map even when selecting outside a previous reading scope, preserving sentence spacing and highlighting. The source command is part of the typed reader contract; rapid Play requests are serialized, and closed or superseded sessions cannot restart from a late response.

Chrome and Firefox product probes now exercise Play on a newly selected paragraph, selection completion, and replay using local English/Czech models and a private virtual audio output. The PDF probes also check the selection command used by Play, exact partial-word boundaries, highlighting, and preservation of scope without a fresh selection. This does not measure physical audio quality, hardware GPU behavior, or target-device latency.


### Compact controls, PDF hyphenation, and speech recovery — 2026-11-01

Language metadata remains in the pinned local voice catalog. Display labels derive the base-language name through the browser's [Intl.DisplayNames](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DisplayNames), retaining the catalog's region names when multiple locales share a language. This avoids a hand-maintained display-name list and adds no network dependency. The voice selector is capped at 148 px; its native option groups and tooltip retain the complete voice, quality, and language information.

The playback surface groups transport, listening adjustments, and voice controls. A speaker button opens a native HTML popover containing the volume slider, following the familiar [player volume-slider interaction](https://support.apple.com/en-ie/guide/music-web-review/apdmfdca8f52/web). The [Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using) handles focus, Escape, and light dismissal. The containing frame grows to fit the panel and positions it beneath the speaker. Because native light dismissal is scoped to the iframe document, window focus loss dismisses the panel when returning to the source page or switching tabs. Escape only closes the player when no volume panel is open. Volume is saved locally, restored before playback, and applies a perceptual square taper through one output GainNode. [AudioParam.setTargetAtTime](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/setTargetAtTime) smooths changes over a 15 ms time constant, avoiding hard gain steps without regenerating speech, changing pitch, or affecting word timing. No UI or inference dependency was added.

PDF extraction now uses PDF.js TextItem `hasEOL` and the supplied text/space items rather than adding a space between every font span. Explicit line-end hyphenation and discretionary soft hyphens are normalized through a shared text/run transformation. Ordinary PDF line endings become spaces; blank lines and page boundaries remain navigation boundaries. Retained runs continue to map unchanged source characters to their original DOM nodes and offsets. Highlighting a joined word therefore covers both printed fragments. Native-viewer selection matching applies the same hyphenation rules, while real inline hyphens and domain dots remain intact. This handles the supplied thesis; arbitrary PDF reading order and ambiguous linguistic hyphenation still require representative-document testing.

The reported acknowledgement/abstract failure reproduced at the Roman-numeral footer `iv`. The bundled eSpeak emits repeated events for expanded numbers/Roman numerals with positions inside a token but the original token's full length; it also emits zero-length word annotations next to closing quotes. Treating these as literal source ranges was incorrect. Valid source spans are retained. Prefix-only compounds and incomplete or overflowing number/quoted-word annotations resolve against ICU word boundaries at the reported Unicode position, merging adjacent hyphenated parts. This preserves word boundaries in scripts without spaces instead of grouping every contiguous letter into one word. `pre-exascale` is highlighted for its complete predicted acoustic duration even when eSpeak reports only the prefix. Unmappable annotations retain pronunciation and omit that annotation's highlight. Actual eSpeak phonemes and the model's acoustic durations remain the source of speech and timing. The old extracted thesis corpus had 38 tokenization failures; the corrected tokenization completed that corpus with none.

A dedicated source-error type crosses the worker boundary and prevents source failures from needlessly reinitializing GPU inference on CPU. The shared speech service retries source-specific failures by bisecting at whitespace, to a maximum depth of three (15 attempts), preserving usable PCM and rebasing its source offsets and acoustic times. An unreadable leaf is skipped, with a visible/accessibly announced playback notice. Three consecutive wholly unreadable chunks stop with an actionable voice/selection message. Runtime, connection, invalid-model, and cancellation failures propagate instead of silently discarding content. A service generation invalidates recovery after cancellation, replacement, or voice deletion, including when the same reader remains connected.

Regression tests exercise the actual bundled browser phonemizer with numbers, Roman numerals, quotes, domain dots, and compounds; normalization/run offsets; bounded recovery and PCM/timing concatenation; runtime-error propagation; and cancellation during recovery. Chrome 155 and Firefox 159 passed the real MUNI cross-page selection and both-fragment/full-compound highlight checks. Their real local English/Czech playback probes verify output gain, mute, persistence, focus, no synthesis/audio restart on volume changes, and native Escape dismissal. A copied-test-package AudioContext subclass observes the real graph without modifying audio behavior. Chrome layout screenshots cover light/dark and narrow controls. Linux VM tests use a private null audio sink; Chrome's isolated test process disables its sandbox because this host blocks its user namespace sandbox. These checks do not establish Windows/Zen compatibility, physical output quality, hardware GPU behavior, or target-device cold latency.
